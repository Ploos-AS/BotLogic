# M1.1 — Non-mutating policy validation

**M1.1 — PASS.**

BotLogic v1 now exposes `POST /v1/validate` for server-side Prolog validation without activating or persisting the submitted source.

Validation uses a fresh interpreter and does not:

- add a ruleset to the Store;
- write a `.pl` or facts file;
- change a ruleset revision;
- replace an active policy.

Valid source returns `ok: true, valid: true`. Invalid Prolog returns HTTP 422. Invalid request shape or empty source returns HTTP 400. The endpoint uses the same 64 KiB request limit as consult.

This primitive allows clients such as Engo to perform a real BotLogic-side dry-run before a later atomic `/v1/consult` activation.

CI, tests, vet and Alpine container build are green.
